# Profile transition and settings navigation stability

The user reports vertical jumps when selecting Profile Posts, Media, Featured and other categories, plus repeated Settings labels in settings children. Baseline is `df7c305`, product 0.6.4 build 10. The root reproduced both on the existing signed-in iPhone 17 Pro simulator without resetting its account or cache.

Selecting Media after partially scrolling the Profile moved the category row from Y 373 to Y 458, an 85-point jump. Media was empty in the actual account. The native assertion expected a maximum 4-point difference. Opening About this server retained the outer Settings title and a second `‹ Settings` button, failing the second native assertion. See `native-baseline.json` and `screenshots/baseline-*`. The screenshots and position attachment were inspected by the root. No product code has changed yet.

The how explainer's full source model is in `grounding.md`. Its distinction between source-keyed list recreation and short-content maximum-scroll clamping is important. A source cache restoration can change header position, and a short body can independently make the old scroll offset unattainable. The baseline demonstrates the empty-Media transition but does not isolate those two mechanisms by itself.

The local-history investigator's full findings are in `history.md`. Prior per-source viewports, an independent About list and accepted nonsticky tabs are bounded agent design choices, not permanent human requirements. Continuous header-to-post reading, account and source separation, status-only cache coordinates, FeedPager cursor ownership and StatusProjection freshness remain constraints. The old capped independently scrolling header must not return. Hidden feeds must not remain active just to preserve UI.

Settings currently has two owners of navigation. Screen.Settings is a single route known to AppShell, while SettingsScreen privately owns a string subsection and the extra back button. A corrected design must give the visible child title and back action one owner. Removing the extra text without preserving a return path to the settings index is insufficient. Preserve all child functionality, authentication gates, existing form handling and source translations.

Architecture comparison must include two structurally distinct whole designs, not only different cache flags. Cover all five Profile categories, short/empty/loading bodies, Activity filters, large text, cache restoration after a child route, source isolation, pending reveal and pagination. Choose a small explicit contract that a maintainer can follow. Root owns the simulator, native harness, builds, versioning and device delivery. No new live post or photo writes are required.

A subsequent empty-body counterexample keeps Media active and drags upward, so no source or cache restoration runs during the gesture. The tab row stays at Y458, failing the expected movement past Y418. This confirms the independent short-content constraint. It does not measure the relative contribution of cache restoration to the original switch. See native-baseline-empty.json and the matching screenshots/position attachment.
