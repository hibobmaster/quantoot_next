# Profile, Home, and gallery interaction ownership

## Overview

The requested result is a profile that scrolls naturally into its posts, compact profile actions, vertical image dismissal, and a Home subtab that survives opening a post. The source at `67d1f79` points to four bounded ownership changes. Profile layout currently splits vertical movement between two containers. Home selection belongs to a composition that navigation removes. The gallery already separates paging, zoom, and saving, but has no vertical dismissal owner.

This is source analysis only. The root agent owns simulator reproduction and validation. The Fix Root Causes principle shaped this analysis by tracing the profile symptom to competing scroll owners and the Home symptom to selection lifetime.

- `FeedSnapshot` stores status rows, a status index, a pixel offset, and the server continuation cursor. It contains no profile header or Home selection. [FeedCache.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/FeedCache.kt:13).

## How It Works

`ProfileScreen` first loads the person and relationship. Its outer `Column` places a header `Column` with `heightIn(max = 380.dp)` and its own `verticalScroll` above the profile tabs. The selected feed then creates another vertically scrolling container inside `FeedScreen`. The cap is a maximum rather than a literal fixed height, but a long header occupies 380dp and stays above the feed while posts scroll. Header movement cannot give that space to the post list. [Accounts.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Accounts.kt:202), [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:213).

A unified profile scroll needs one list owner for the header, profile tabs, optional Activity filters, and status rows. Feed loading, projection, refresh, pending arrivals, and pagination should remain with the existing feed machinery. Rendering `FeedScreen` inside an unconstrained parent vertical scroll leaves two list owners and measurement problems. The About tab also currently creates a separate `verticalScroll`, so the shared profile structure must cover that branch. [Accounts.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Accounts.kt:350).

The current header gives the self Edit action a full row, self Favorites and Bookmarks another row, and QR and Share a further row. Other profiles have a full Follow row plus moderation overflow, then the QR and Share row. A compact action row can preserve a primary text action with remaining width and small secondary controls beside it. Existing handlers must retain their owners. Follow, mute, block, and report still use `changeRelationship` and `relationshipBusy`. QR still opens the local `ProfileQr`, Share still validates `person.url`, and self Favorites and Bookmarks still navigate to their distinct feeds. Preserve accessible labels and touch targets even when secondary controls use icons. [Accounts.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Accounts.kt:170), [Accounts.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Accounts.kt:219).

Home selection starts as `0` for a signed-in user or `1` for a guest. Selecting Federated sets local selection to `2`. Opening a status pushes `Screen.Thread`. `AppShell` keys its entire current screen by the route and tab, so Home leaves composition. Back removes the thread route and reconstructs Home, whose `remember` starts at its default again. FeedCache cannot resolve this because `FeedScreen` receives its source after Home has already chosen that source. Keep the selected Home subtab in the existing `AppShell` lifetime outside the route key and pass its value and callback to Home. The existing outer account key provides the account boundary without a navigation framework. [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:30), [QuanTootApp.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/QuanTootApp.kt:114), [QuanTootApp.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/QuanTootApp.kt:265).

The gallery begins with a copied attachment list, so stream edits cannot replace the open gallery's pages. `HorizontalPager` accepts horizontal swipes only at scale `1`. `GalleryImage` consumes movement when multiple pointers are down or when the image is zoomed. At scale `1`, a single vertical drag has no handler and no dismissal callback. A dismissal handler must arbitrate one-finger vertical movement against horizontal paging after touch slop. Both upward and downward movement count. A horizontal decision must stay with paging, and a multi-pointer or zoomed decision must stay with image transformation. The gallery owns `onDismiss`, so image gesture code needs a bounded callback rather than a route-stack change. Native video controls and the scrolling ALT panel should retain their gestures. [MediaAttachments.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/MediaAttachments.kt:72), [MediaGallery.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/MediaGallery.kt:196), [MediaGallery.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/MediaGallery.kt:297).

Saving captures a `GallerySaveTarget` before launching the operation. `GallerySaveState` rejects duplicates while saving. Failure feedback retries its captured target, even if the user has changed pages. Page changes reset zoom, not save state. Gesture changes must preserve that shared state and its local feedback. Dismissal currently cancels the composition's save coroutine just as the existing Close button does, and cancellation returns the state to Idle. The source does not promise that dismissing a gallery keeps a save running. [MediaGallery.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/MediaGallery.kt:57), [MediaGallery.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/MediaGallery.kt:153), [GallerySaveStateTest.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonTest/kotlin/com/quanquan/quantoot/ui/GallerySaveStateTest.kt:16).

## Gotchas

`rememberFeedPager` currently writes the raw first visible list index into the status-only snapshot. Restoration reads `saved.items[saved.index]` as an anchor, locates it among projected status rows, and scrolls to that index. Adding even one header item changes this coordinate system. Saving needs list-to-status translation, and restoration needs status-to-list translation. A header-visible pixel offset cannot become the first status's pixel offset. If the intended return position is inside the header, that requires an explicit representation. Cache writes clamp indices to at most the last stored status, so raw mixed-list coordinates would silently corrupt restoration rather than reliably fail. [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:113), [FeedCache.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/FeedCache.kt:60).

The same change affects `readingOlder`, pending-arrival `scrollToItem(0)`, and pagination's visible-index and total-item calculations. Their present meaning assumes the first list item is the first post. A grouped prefix gives a stable prefix count but does not solve these assumptions alone. Preserve cache identity by instance, account, and full timeline filters. [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:112), [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:148), [Feeds.kt](/Users/bobmaster/Projects/QuanToot_Next/shared/src/commonMain/kotlin/com/quanquan/quantoot/ui/Feeds.kt:204).
